# Linux desk signer: first-cut launch kit

This kit is opt-in. It does not enroll names, rotate DIDs, install on a host by itself, or integrate with a terminal manager's spawn RPC. The launch broker is operator-only. Never delegate it to the client UID via sudo, Polkit, or a socket.

For a disposable trial, first stage a reviewed Node 24 release with its workspace dependencies under `/opt/ratking-signer`. All files, directories, dependency targets and ancestor directories must be trusted and not replaceable by the desk UID. Do not run the installer or worker as root from a writable checkout. `install.sh` is a one-time, separately approved step; it adds the signer UID, custody and profile directories, launcher and a stopped system unit. It does not remove access to rootful Docker. That access invalidates the custody boundary; qualify it separately, including still-running sessions. Check host crash-dump handling before putting real keys in this service.

A root-owned `0600` profile in `/etc/ratking-desk-signer/<profile>.json` names a single canonical Rat King identity, a non-root client account, its absolute command, and optionally `cwd`. For example, `{"name":"example","user":"desk-user","argv":["/usr/local/bin/pi"]}`. Root controls the invocation; profile arguments may not contain secrets. Both subprocesses get a narrow environment and no supplementary groups. The signer reads one `0600` identity JSON owned by `ratking-signer` under `/var/lib/ratking-desk-signer`, named `<hex SHA-256 of the canonical name>.json`. Do not place even a temporary copy in client-readable storage. The identity must match the DID and public keys trusted by the mailbox.

In the client's Rat King config set `"signerNames": ["example"]`. This fails closed without a grant even if a legacy key is still present. The launcher gives the client an inherited connected socket; the environment contains only its fd number. Use the installed launcher from an authorized terminal for an interactive test, or explicitly start the instance unit for a noninteractive profile. The unit has no enable stanza or automatic restart. Do not reuse the fd after a process restart: retire the old holder and obtain a new approved launch. A protected `--as` command needs its own authorized invocation; the name option is not a mint. Keys, broker provenance, real UID separation, restore, rotation and live mailbox behavior are qualification gates, not asserted by the fixture.

Run the Linux process fixture without sudo: `python3 -B scripts/desk-signer/test_launch.py`. It uses ephemeral generated keys and a same-UID fixture; it tests the kernel PID gate, not file isolation between real users.
